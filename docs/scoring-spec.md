# 评分口径与算法说明

本文对应 `index.html` 中的 `compute()` / `detect()` / `autoFix()`，是 UI 内「评分口径与当前规范」弹层的完整版。改动评分需同步三处：代码、弹层文案、本文档。

版本：1.1.0（评分口径与 1.0.0 兼容，默认配置下结果一致）

## 一、行数估算

手机上「一段占几行」不是字符数决定的，而是宽度决定的。估算分三步：

1. **可用宽度**：当前屏宽（默认 375px）− 左右各 16px 内边距。
2. **每行容量**：可用宽度 / 当前字号 = 每行可容纳的 em 数。375px、15px 时约 22.86 个汉字。
3. **文本宽度**：逐字符累加 em 宽度。

| 字符类型 | 宽度系数 |
| --- | --- |
| 汉字、全角标点 | 1.00 |
| 空格 | 0.30 |
| 数字 0—9 | 0.55 |
| 大写字母 | 0.62 |
| 小写字母 | 0.53 |
| 其他 ASCII | 0.40 |

行数 = `ceil(文本宽度 / 每行容量)`，最小为 1。

> 该口径与微信真机渲染通常相差 ±1 行。字号切换（14/15/16/17）与屏宽切换（360/375/390/414）都会实时改变容量，因此同一篇稿子在不同设置下得分可以不同——这是刻意的：排版是相对字号与屏宽成立的。

## 二、段落呼吸感 · 30 分

仅统计非标题段落。设单段行数上限为 `L0`（默认 4，可配 3/4/5），每段先按下表折算成 0—100 的单段得分，再取平均，最后乘以 0.30。

| 折算行数 | 单段得分 |
| --- | --- |
| ≤ L0 | 100 |
| L0 + 1 | 78 |
| L0 + 2 | 52 |
| L0 + 3 | 28 |
| > L0 + 3 | `max(6, 28 − (行数 − L0 − 3) × 6)` |

理由：手机单屏可容纳约 20 行正文，一段占 7 行意味着读者要在一屏之内面对一个没有落点的文字块，弃读率显著上升。

## 三、句子长度 · 25 分

按 `。！？!?；;` 切句，去掉空白与标点后计字数，只统计长度 ≥ 6 的句子（避免把小标题、语气词计入）。取平均后乘以 0.25。

| 单句字数 | 单句得分 |
| --- | --- |
| ≤ 30 | 100 |
| 31—40 | 80 |
| 41—50 | 58 |
| 51—70 | 32 |
| > 70 | 12 |

## 四、结构层级 · 20 分

四项累加：

| 检查项 | 分值 | 判定 |
| --- | --- | --- |
| 有小标题 | 8 | 至少识别出 1 个标题段落 |
| 段落数量 | 4 | 正文段落数在 3—25 之间 |
| 首段长度 | 4 | 第一段折算行数 ≤ 单段上限 |
| 标题留白 | 4 | ≥ 60% 的小标题在上方或下方存在空行 |

标题识别规则（命中任一即为标题，长度上限 24 字）：

- 以 `第X，`、`一、`、`1.`、`(1)`、`【`、`#`、`▍/●/◆/■` 开头；
- 14 字以内且以 `：` 结尾；
- 12 字以内、无句末标点、且视觉宽度 ≤ 13em。

例外：以句末标点结尾且长度 > 14 字的句子**不算**标题——「第一，一段不超过 4 行，让眼睛有地方休息。」是一句正文，不是小标题。

## 五、标点与规范 · 25 分

从 25 分起扣，扣完为止。**只统计已开启的规则**：

| 规则键 | 问题 | 扣分 | 说明 |
| --- | --- | --- | --- |
| `spacing` | 中英文 / 数字 / 百分号紧贴汉字 | 每处 1，上限 8 | 「超过8行」应为「超过 8 行」 |
| `punct` | 中文句中用半角逗号、冒号、分号 | 每处 1，上限 6 | `,` `:` `;` 应为 `，` `：` `；` |
| `repeat` | 连用感叹号、问号、句号、逗号 | 每处 2，上限 6 | `!!` `。。` `，，` |
| `ellipsis` | 用三个英文点代替省略号 | 每处 1，上限 3 | `...` 应为 `……` |
| `whitespace` | 段首 / 段尾多余空白 | 每处 1，上限 4 | 公众号会自动首行缩进 |
| `whitespace` | 含全角空格 | 1 | 部分机型宽度不一致 |
| `blanks` | 连续空行 | 2 | 保留一个即可 |
| `trailingEN` | 中文句子用英文标点收尾 | 每处 1，上限 4 | 句尾 `.` `,` `:` `;` `!` `?` 应为全角 |

维度说明会列出实际扣分来源（如「空格 12 处；半角标点 20 处」），而不是只给一个数字。

## 六、可配置项

| 配置 | 取值范围 | 默认 | 影响 |
| --- | --- | --- | --- |
| `viewport` | 360 / 375 / 390 / 414 | 375 | 每行容量 → 行数 → 段落分与结构分 |
| `lineLimit` | 3 / 4 / 5 | 4 | 段落呼吸感阈值、预览着色、长段拆分目标 |
| `fontSize` | 14 / 15 / 16 / 17 | 15 | 每行容量 |
| `lineHeight` | 1.6 / 1.75 / 2.0 | 1.75 | 仅影响预览观感，不参与评分 |
| `rules.*` | `true` / `false` | 全开 | 参与扣分、改稿清单与一键修复 |

配置与草稿一起存在 `localStorage` 的 `paiban-yisheng-config`，键名固定；规则键见上表。

## 七、总分与等级

`总分 = round(段落 + 句子 + 结构 + 标点)`，取值 0—100。

| 分数 | 等级 | 含义 |
| --- | --- | --- |
| ≥ 90 | 通透 | 可以直接发 |
| 80—89 | 清爽 | 小幅打磨即可 |
| 70—79 | 尚可 | 有 1—2 个维度明显拖后腿 |
| 55—69 | 需要改 | 建议先按清单改一遍 |
| < 55 | 读起来累 | 排版结构性问题，需要重排 |

诊断文案取**得分率最低**的维度（得分 ÷ 满分），并附上该维度的具体建议。稿子不足 120 字时追加样本过短的提示。

## 八、一键修复的边界

`autoFix()` 只做机械替换，按以下顺序执行，每步受对应规则开关控制：

1. `whitespace`：清理段首段尾空白、全角空格转普通空格；
2. `repeat`：连用感叹号 / 问号归一，重复句读归一；
3. `ellipsis`：`...` → `……`；
4. `punct`：中文语境下的半角逗号、冒号、分号转全角；
5. `trailingEN`：句尾 `.` `!` `?` `:` `;` 转全角；
6. `spacing`：汉字与英文 / 数字 / `%` 之间补空格；
7. `blanks`：三个以上连续空行归一为两个；
8. `splitLong`：超过行数上限的段落，**仅在句末标点处**拆成多段。

不做的事：

- 不在逗号处断段——会在段末留下半截逗号，也等于替作者决定了语义；
- 不删除、不重写任何句子；
- 不调整字号、图片、间距等排版参数。

因此修复后可能仍有长句提示，这是正常的：格式交给机器，句子交给人。

`autoFix` 是幂等的：对同一输入连续调用两次，第二次返回相同结果。

## 九、修复对比

一键修复时保存 `{ before, after, beforeScore, afterScore }` 快照。对比视图按以下步骤生成：

1. 两版各自按换行切成非空段落数组；
2. 对段落数组求 LCS，得到 `same / del / ins` 操作序列；
3. 相邻的 `del` 与 `ins` 合并为「改动块」，逐对做字符级 LCS；
4. 未改动的字符渲染为普通文本，删除的字包 `<del>`、新增的字包 `<ins>`；
5. 连续 3 段以上未改动的内容折叠为「⋯ N 段未改动 ⋯」。

单块超过 600 字时退化为整块对比，避免 O(n·m) 计算拖慢渲染。

## 十、实现注意

- 标点替换类正则一律使用 `[ \t]*` 而非 `\s*`——`\s` 会吞掉换行，导致小标题被合并进下一段。
- 段落以单个换行切分，符合「粘进来的纯文本一行一段」的实际习惯。
- 所有渲染走 `textContent`；富文本复制用 `DOMParser` 解析后 `importNode`，不拼接 `innerHTML`。
- 草稿写入做 350ms 防抖，避免每次按键都序列化整个草稿库。
